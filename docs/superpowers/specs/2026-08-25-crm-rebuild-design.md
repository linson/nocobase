# CRM 重建设计（官方设计 + 开源实现）

日期：2026-08-25
状态：已批准（用户确认执行）

## 背景

- 目标实例：本仓库源码安装的 NocoBase 2.2.1（开源版），PostgreSQL 18，`http://localhost:13000`。
- 官方 CRM 解决方案的 `.nbdata` 备份包由商业发行版的 pg_dump 机制生成，开源版还原插件无法消费，且引用 28 个本地不存在的商业插件。
- 备份已还原到参考库 `crm_ref`（独立数据库，不动主库），其设计资产（数据模型 / 页面 / 工作流 / 角色）全部与开源字段类型兼容。

## 范围

从 `crm_ref` 提取官方 CRM 设计，在主实例用开源插件重建：

1. **数据模型**：30 个 `nb_crm_*` / `nb_cbo_*` 集合（线索、客户、联系人、商机、报价、订单、产品、回款、汇率、标签等）及全部字段与关联。
2. **页面**：桌面菜单（三角色工作台：销售代表 / 销售经理 / 高管；线索、客户、商机管道、订单、产品、联系人、数据分析、合并去重等）。
3. **角色与权限**：销售代表 / 销售经理 / 高管，含菜单授权与数据隔离（销售只看自己名下，管理层全局）。
4. **工作流**：线索自动分配、线索转化、跟进提醒、线索评分、客户合并、AI 经营分析（plugin-ai 开源）；**报价审批用 workflow-manual 重写**（替代商业 workflow-approval）。
5. **演示数据**：默认导入（线索/客户/联系人/商机/报价/订单及演示用户），提供清除脚本。
6. **舍弃**：邮件集成（商业 email-manager）、AI 知识库（商业）。

## 实施形态

- 脚本目录：`scripts/crm-import/`
  - `extract.ts`：从 `crm_ref` 提取设计到 JSON（collections/fields、desktopRoutes、uiSchemas、flowModels、workflows+节点、roles+ACL、演示数据）。
  - `build.ts`：将设计 JSON 重放到主实例（REST API + 管理员 token），内部维护官方 snowflake id → 本地新 id 的映射。
- 所有写入走应用层 API，不直接写主库元表；业务演示数据在表结构由应用创建后按表导入。
- 执行前已有空库快照（`storage/backups/pre-crm-restore-*.dump`）兜底。

## 风险与对策

- **元表版本差异（2.1.0-beta.36 → 2.2.1）**：提取时以 2.2.1 的元表列为准裁剪/补默认值；逐表比对列差异后再重放。
- **UI 区块组件差异**：flowModels/uiSchemas 引用的组件若在 2.2.1 更名，导入后逐页面验证并替换坏区块。
- **id 映射**：集中在 build.ts 的映射表；演示数据中的外键引用同步改写。
